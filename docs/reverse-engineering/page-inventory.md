# Page Inventory — index

This file is deliberately **not** a copy of the page table. The complete, verified inventory of all 383 pages
already exists at [`specs/INVENTORY-PAGES.md`](../../specs/INVENTORY-PAGES.md) — duplicating it here would just
create a second copy that can drift out of sync. Read this file for orientation, then go there for the actual
table.

## What `specs/INVENTORY-PAGES.md` contains

One row per `.aspx` file (383 rows), generated by walking `Solution.Web/**/*.aspx` and excluding
`PrecompiledWeb` (stale build output — see `GAP-STR-004`). Columns:

| Column | Meaning |
|---|---|
| Page ID | e.g. `SAL-014` — module prefix + sequence |
| Module | one of the 11 INFERRED modules (see [`module-inventory.md`](module-inventory.md)) |
| Page name | the `.aspx` file name |
| Route | web-relative path |
| Master page | `MainMasterPage` or **none** — **the "none" pages are exactly the ones with no session/auth guard** |
| Code-behind class | Web Forms auto-generated class name (there is no MVC controller/action — code-behind *is* the action) |
| Markup LOC / CS LOC | rough size |
| Controls / Grids / Methods | counts feeding the totals in [`system-inventory.md`](system-inventory.md) |
| Spec | link to the page's full 31-section spec under `specs/<module>/pages/PAGE-<ID>-<Name>.md` |

There is no "View" or "Controller/Action" split in this application (Web Forms) — the "Master page" and
"Code-behind class" columns are the closest equivalents: the `.aspx` is the view, the `.aspx.cs` class is both
controller and action combined. See [`dependency-map.md`](dependency-map.md) for the full request-to-database
chain.

A companion table at the end of `specs/INVENTORY-PAGES.md` adds one more column per page: **"checks session
itself?"** — whether the page performs its own auth check independent of the master page. That table is the
source of the finding below.

## The most safety-critical fact in this file: `GAP-SEC-002`

**127 of the 383 pages have no authentication guard.** The only session check in the entire application lives in
`MainMasterPage.master.cs`. 256 pages use that master page; the other 127 — mostly report viewers that read
their parameters straight from the query string — do not, and can be requested by anyone without logging in.

- Full per-page list with the "checks session itself?" column: end of [`specs/INVENTORY-PAGES.md`](../../specs/INVENTORY-PAGES.md).
- Finding detail: [`specs/SPEC-GAPS.md`](../../specs/SPEC-GAPS.md) → `GAP-SEC-002` (severity: **critical**).
- The correct pattern to follow for any new page is `MainMasterPage.master.cs`'s session check — see
  [`.claude/SKILL.md`](../../.claude/SKILL.md) → Security rules.

## Completeness

Per-page, per-area completeness (UI/backend/DB/business-rules/permissions/status/tests) is tracked in
[`specs/SPEC-COVERAGE.md`](../../specs/SPEC-COVERAGE.md) — not duplicated here either. Headline: **no page is
